# SAB SOP preservation repair

This is an implementation/verification record, not an SOP amendment. The sole integrated procedure is `sab-scale-first-sop.md`, synchronized to the existing shared Google Doc. The original source snapshot and explicitly approved replacements were compared before restoration; obsolete supervisor, five-pin, two-ring, scout-boundary-veto and routine reread rules remain removed.

## Restored operating instructions

- Original email acceptance gates, contradiction veto, focused visual search completion, rejected-candidate history, returned-phone retention and optional verified-owner handling.
- Required address corroboration before an unresolved initial-center auxiliary, with approved centering routes taking precedence; incomplete evaluation holds the affected company and never means failed corroboration.
- Exact pending/completed report checks, master survivor reconciliation, immutable Sheet/tab identity, submission/pending/retry handling, history preservation, funnel accounting and stage checklists.
- Optional one-time same-center five-mile comparison after a validated three-mile deliverable, without retroactive centering changes.
- Complete enrichment profile, privacy handling, reverse-geocode completeness, report generation/contact routing, actual scan specifications and prospect-facing ATRP with the 20+ display cap.

## Connector corrections

- Connector release identifier: `2.1.0`; tool inventory: 31. CRM manifest contract: `2.3`, with backward-compatible optional `business_profile`.
- Five-mile comparison has a separate decision outcome and retains the completed three-mile center validation. S09 still requires the testing exclusion review; S08 still selects five miles only when raw ARP increases AND SoLV decreases. No comparison-driven recenter or repeated comparison is authorized.
- `record_sab_address_corroboration` records measured private-candidate evidence and a structured fit disposition. Generic workflow edits cannot forge, remove or relabel corroboration evidence or clear its hold; the dedicated recorder and verified analysis paths handle legitimate resolution.
- New batch authorization requires `duplicate_report_checks` bound to each exact scan plan, with a none result, check time and evidence reference. Existing stored authorizations remain readable.
- Compact enrichment survives workflow, manifest and both CRM outcomes. Existing lead-note JSON metadata stores typed import provenance, retrievable by exact Place ID; prose notes never establish qualification or scan state. No database migration is required.
- Reverse-geocoder responses retain `formatted_address: null` for compatibility and suppress provider error text. Tool descriptions distinguish final-center geography from auxiliary market references and explain incomplete-evidence holds.
